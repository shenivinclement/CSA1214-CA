  1.  RUN THE BACKEND  --  ONE CLICK
-------------------------------------------------------------------------------

  Double-click:        START-BACKEND.bat

  That is all. It will:
      * check that Node.js is installed
      * start the server on port 3000
      * open http://localhost:3000 in your browser automatically

  KEEP THAT BLACK WINDOW OPEN while you demo.
  Closing it (or pressing Ctrl+C) stops the backend.

  To run the tests instead, double-click:   RUN-TESTS.bat


  If you prefer typing it yourself, open a terminal in this folder and run:

      npm run dev

  (There is nothing to install first -- this project has zero dependencies.)

-------------------------------------------------------------------------------
  3.  WHAT THE BACKEND IS  (the one-line version for your viva)
-------------------------------------------------------------------------------

  The assembler and both CPU engines live in  public/core/  as plain ES modules
  with no browser code and no server code in them. The SAME files are imported
  by:

      - public/js/ui.js   the browser trainer      (interactive stepping)
      - api/*.js          the serverless functions (batch assemble / run)

  This is called an ISOMORPHIC CORE. There is one instruction table per
  processor, so the browser and the server can never disagree.

  The "Server" tab in the app proves it: it runs your program on BOTH engines
  and compares every register, every flag and every memory range side by side.


  Folder map
  ----------
      public/                  <- everything Vercel serves to the browser
        index.html
        css/style.css
        js/ui.js               browser UI + API client
        core/common.js         hex helpers, error types
        core/expr.js           expression evaluator ($ , HIGH/LOW, + - * /)
        core/cpu8085.js        8085 encoder + execution engine
        core/cpu8086.js        8086 encoder + execution engine
        core/assembler.js      two-pass assembler driver
        core/runner.js         headless assemble+execute (API and browser)

      api/assemble.js     POST /api/assemble
      api/run.js          POST /api/run
      api/health.js       GET  /api/health
      api/_lib.js         shared HTTP helpers (underscore = not a route)

      server.mjs          local dev server (serves public/ + /api)
      tests/              49 automated tests

  The engine sits inside public/core/ so the browser can import it over HTTP,
  and the serverless functions import the SAME files via ../public/core/.


-------------------------------------------------------------------------------
  4.  THE THREE API ENDPOINTS
-------------------------------------------------------------------------------

  GET  /api/health      status, supported instructions, limits, and a
                        self-test that really executes an 8085 program

  POST /api/assemble    assemble only -> listing, symbol table, machine code

  POST /api/run         assemble AND execute to HLT -> final registers, flags,
                        memory dumps, console output, execution trace


  Status codes
  ------------
      200   worked (including a program that faulted at runtime --
            a divide-by-zero is a normal result for a trainer, so you
            get 200 with a "fault" field set)
      400   your request was malformed (missing source, bad arch, bad range)
      405   wrong HTTP method
      422   the program failed to ASSEMBLE (syntax errors)

  Safety limits (enforced server-side)
  ------------------------------------
      max source            128 KB
      max instructions      5,000,000
      max wall clock        5 seconds
      memory dump ranges    up to 8, max 4096 bytes each

  So an infinite loop returns  stopReason: "instruction-limit"  instead of
  hanging the server.


-------------------------------------------------------------------------------
  5.  DEMO COMMANDS  (copy-paste into PowerShell)
-------------------------------------------------------------------------------

  NOTE: in PowerShell use  curl.exe  (not plain "curl"), and use a semicolon
  ";" to join commands -- "&&" does not work in Windows PowerShell.


  --- Health check -------------------------------------------------------

  curl.exe http://localhost:3000/api/health


  --- Assemble an 8086 program ------------------------------------------

  curl.exe -X POST http://localhost:3000/api/assemble -H "content-type: application/json" -d "{\"source\":\"ORG 100H\nSTART: MOV AX,1234H\nHLT\",\"arch\":\"8086\"}"

  Returns:  "hex": "B8 34 12 F4"   and the symbol table with START = 0100


  --- Run an 8086 program and read memory back --------------------------

  curl.exe -X POST http://localhost:3000/api/run -H "content-type: application/json" -d "{\"source\":\"ORG 100H\nMOV AX,1234H\nMOV BX,4321H\nADD AX,BX\nMOV [3000H],AX\nHLT\",\"arch\":\"8086\",\"memory\":[{\"start\":12288,\"length\":2}]}"

  Returns:  AX = 5555, and memory at 3000H = "55 55"
  (12288 decimal = 3000 hex)


  --- Run an 8085 program -----------------------------------------------

  curl.exe -X POST http://localhost:3000/api/run -H "content-type: application/json" -d "{\"source\":\"ORG 2000H\nMVI A,05H\nMVI B,03H\nADD B\nSTA 2050H\nHLT\",\"arch\":\"8085\",\"memory\":[{\"start\":8272,\"length\":1}]}"

  Returns:  A = 08, and memory at 2050H = "08"


  --- Show the safety limit working -------------------------------------

  curl.exe -X POST http://localhost:3000/api/run -H "content-type: application/json" -d "{\"source\":\"ORG 2000H\nL: JMP L\",\"arch\":\"8085\",\"maxInstructions\":5000}"

  Returns:  halted:false, stopReason:"instruction-limit"


-------------------------------------------------------------------------------
  6.  A GOOD 3-MINUTE DEMO ORDER
-------------------------------------------------------------------------------

  1. Double-click START-BACKEND.bat -- browser opens by itself.

  2. Point at the green "API - online" badge in the toolbar.
     Say: the frontend checked the backend's health on page load.

  3. Type a short program, e.g.

           ORG 2000H
           MVI A,05H
           MVI B,03H
           ADD B
           STA 2050H
           HLT

     Press Assemble, then press "Micro-Step (FSM)" five times.
     Say: Fetch -> Decode -> Operand Fetch -> Execute -> Write-back.
     Registers only change on Write-back.

  4. Press "Run" -- watch the registers, flags and memory update.

  5. Press "Run on Server", then open the "Server" tab.
     Say: the same program just ran on the backend AND in the browser,
     and all N values matched -- because both import the same
     public/core/ engine.

  6. Show the raw API: paste the /api/health curl command.

  7. Double-click RUN-TESTS.bat -- 49 tests pass.


-------------------------------------------------------------------------------
  7.  DEPLOY TO VERCEL
-------------------------------------------------------------------------------

  There is NO build step. Vercel serves the files as-is and turns every file
  in api/ into a serverless function automatically.

  On https://vercel.com/new , import the repo  shenivinclement/CSA1214-CA
  and set:

      Framework Preset ....... Other
      Root Directory ......... virtual-trainer      <-- IMPORTANT, type this
      Build Command .......... leave EMPTY
      Output Directory ....... leave EMPTY
      Install Command ........ leave EMPTY

  Then press Deploy. Every future "git push" redeploys automatically.

  WHY "Root Directory = virtual-trainer" MATTERS
  ----------------------------------------------
  The CSA1214-CA repo also holds your coursework: 30 scanned .jpg pages,
  9 assessment PDFs, and your report .docx files.

  Anything Vercel deploys is downloadable by ANYONE who guesses the URL.

  Setting Root Directory to "virtual-trainer" means Vercel never even sees
  the rest of the repository -- only the app folder is uploaded. That is a
  hard boundary, not a filter. Leave it blank and your scanned assignments
  would be served publicly.

  ( .vercelignore inside the app folder is a second layer of protection:
    it blocks *.docx, *.pptx and *.pdf from being uploaded. )

  After deploying, your API is live at:

      https://<your-app>.vercel.app/api/health


-------------------------------------------------------------------------------
  8.  TROUBLESHOOTING
-------------------------------------------------------------------------------

  "Node.js was not found"
        Install the LTS version from https://nodejs.org, then reopen the .bat

  "EADDRINUSE" / port 3000 already in use
        Another copy is already running. Close the other black window, or
        start on a different port:      node server.mjs 3001

  Badge says "API - offline"
        The backend is not running. Double-click START-BACKEND.bat.
        The trainer still works -- everything falls back to the browser engine.

  Blank page / "Failed to load module script"
        You opened index.html directly from the folder. Use
        START-BACKEND.bat and go to http://localhost:3000 instead.

  "&&" error in PowerShell
        Windows PowerShell does not support &&. Use a semicolon instead:
              cd "C:\path\to\project" ; npm run dev

  Stop the server
        Click the black window and press Ctrl+C, or just close the window.
